# 戦闘機シリーズ共通・速度調整レバー契約 v1

2026-10-05。加速・減速のタッチ2ボタンを、上下操作の1本のレバーへ統一する変更。作品ごとの武器・勝敗・難易度・機体・カメラは変更しない。

## 操作の意味

- Normalの旧加速/減速タッチボタンを置換する。Easyの自動巡航とその入力制限は維持し、Easyにはレバーを追加しない。
- 上へ倒すと目標速度を上げ、下へ倒すと下げる。倒し量に連続比例する速度調整レバーであり、位置で実速度を瞬間指定しない。
- 中央は「保持」。手を離すとレバー表示と入力は中央へ戻るが、調整済みの目標速度は保持する。機体は既存の空力に従ってその目標へ近づく。開始/リトライの目標速度初期化は従来どおり。
- 正規化された倒し量は上+1、下-1。絶対値0.08以下は0、範囲外を±1に制限した後、残りを `(abs(x)-0.08)/0.92` で連続変換する。非有限値・不正なレール寸法は0。
- 目標速度の最大変更率18 m/s毎秒、範囲65..141 m/sを保持する。最大倒し=旧ボタン長押し、中央=旧ボタンを離した状態。Easyの巡航110 m/sと既存controller初期化は変えない。
- 既存の変更可能なPC加速/減速キーは±1で同じ入力経路へ接続する。両キー同時は0。キーとタッチ/フォーカス操作は加算し±1で制限する（例：上0.5と減速キーは-0.5）。入力源を二重に数えない。
- 新しい任意の `FlightInput.throttle` が存在するときは0も含めこれを正本にし、未指定時だけ旧accelerate/brakeを読む。既存のAI・録画・テストとの互換を保つ。

## 所有と解除

- レバーは1つのpointer IDだけを所有する。別の指で操縦・射撃・宙返り/作品固有兵装を同時利用できる。既に他操作を所有する指がレバー上を通っても所有権を奪わない。
- pointer captureを使い、レール外へのドラッグも上下限で継続する。2本目のレバー指は先の指を上書きしない。pointerup/cancel/lostcaptureは所有中の指だけを解除し、他の操作は維持する。
- 非主ボタン、無効モード、非プレイ状態は受け付けない。mouse buttons=0、pause、blur、pagehide、visibility hidden、resize/orientation、設定表示/変更、mode変更、restart/home/result/disposeで入力を0にしてcaptureを解放する。復帰時は新たな押下を必要とし、自動で再開しない。
- タッチの既存stale-primary復旧仕様を保持し、レバー所有もその対象にする。捕捉失敗・途中解除で入力を残さない。IME/編集欄/ブラウザーショートカットをゲーム入力にしない。

## 表示・アクセシビリティ

- ラベルは「速度レバー」、上「加速」、中央「保持」、下「減速」。位置と文字で状態を伝え、色/数値だけに依存しない。handleとhit areaは44 CSS px以上。タッチ域はレバー自身に限り、他の操作・背景の操縦域・設定画面スクロールを透明な巨大領域で覆わない。
- 縦方向のsliderとしてアクセシブル名、説明（離すと中央・速度は保持）、orientation、min=-100/max=100/now、状態に応じたvaluetextを提供する。フォーカス可能で目立つfocus ringを持つ。
- レバーにフォーカスがあるときArrowUp/Right・Endは+1、ArrowDown/Left・Homeは-1として保持中だけ動作、対応keyupで解除。Escape/focusoutも解除。再発火repeatで失効済み入力を復活させない。標準操縦キーとの二重処理を防ぐ。通常のカスタムPCキー設定は維持する。sample前に完了する短いキー/支援技術の調整も最低1回の実際に消費されるsimulation tickへ伝える。sample後に固定stepが0回のframeでも消さず、追いつき処理の複数tickへ短押しを繰り返し再生しない。ただしcancel/blur/pause等の中断では未消費入力を破棄し、復帰時に再生しない。
- レバーは幅=通常のcontrol display size（最小44）、高さ=幅の2倍を基本にし、handle中心は上下端から22px以上内側。設定と実画面で同じ長方形寸法を使い、safe-area/visualViewport/縦横で全体を収める。極端に小さい画面では実際に使える寸法へ安全縮小し44px hit areaを維持する。
- touch設定は旧「加速」「減速」を「速度レバー」1項目にまとめる。左右・上下位置、大きさ、不透明度の既存編集方法で左右利きに対応。プレビューも縦レバーであり、2個のボタンを残さない。表示・操作説明・ルール・キー説明を整合させる。

## 保存互換性

- 旧v1タッチ保存キーのraw本文は書換えも削除もしない。新規作品固有v2キー（normal/easyそれぞれ）へ明示Save時だけ書く。ロード/プレビュー/Cancelでは書かない。キーバインドの既存専用キー/形式は維持する。
- 旧accelerate/brakeの有効な配置の中点を候補にし、size/opacityを安全に統合する。既存fire/loop/兵装配置を動かさず、レバーだけ長方形safe boundsへclampする。候補が他操作のhit areaと重なるなら最寄りの安全候補へレバーを退避する。旧両配置のrawは旧キーに残る。安全候補が存在しない場合は既存操作を勝手に移動せず、競合を表示して保存を止める。実画面では重なるレバーだけを無効化/非表示にし、画面回転または設定調整の説明を提示する。解消後のみ有効化し、他の操作を覆わない。
- 新規v2が存在する場合はv1へ逆戻りしない。未来versionはロード時に安全fallbackし、そのrawを保存で上書きしない。v2不在で旧キーが未来形式なら推測移行せず保存を拒否する。壊れたJSONと非有限/欠損数値は安全な既定値で扱う。
- 複数モード/キーを同時保存するときは各キーの許容versionを個別に判定し、全件preflightしてからwriteする。途中失敗は元のrawへrollbackし、メモリ入力設定を変えない。保存できない場合の既存「今回だけ使う」フローを維持する。rollbackそのものが拒否される場合も検査し、更新前に確保した復元用raw控え/allowlist付きrecovery記録を失わない。完全復元できない状態を成功と報告せず、再読込時も安全な旧設定/控えで整合を保ち、復元未完了を表示する。v1控えを消さず、v2から復元可能な設計にする。

## 同一性・受入

- `throttle-lever.ts`共通純関数と`throttle-lever-v1.json`の内容hashを各repoで記録する。repo別adapterは意図的な兵装/保存キー/画面差だけ。fixtureをコピーするだけで合格とはせず、実際の入力sampleから製品の速度更新経路（advanceThrottleまたはsimulationのstepGame等）へ接続して試験する。
- 共通fixture全件、deadzone境界・非有限・範囲外、legacy入力、明示0、Normal/Easy、target保持/上下限/既存加速率を単体試験する。
- pointer複数所有/指跨ぎ/領域外/解除/失効復旧、キー同時/再割当/IME、pause/blur/visibility/mode/restart、タッチと射撃/操縦同時を検査する。
- 旧v1のカスタム左右配置・未設定・破損・未来形式・storage拒否/途中失敗、複数回連続保存→閉じる→開く→reload、Cancel・今回だけ使うを検査する。旧rawのbytes一致を確認する。
- 関連単体検査を修正単位でまとめ、最終候補で全unit/type/buildと必要なChromium/WebKitブラウザー検査を行う。縦320×568/393×852、横568×320/852×393、200%文字/ズーム、safe-areaと設定スクロール、44px最小域を確認する。
- 同条件の変更前後画像で機体/カメラ/既存画面の継承を確認し、変更したレバー領域だけを説明する。模擬WebKitをiPhone実機とは呼ばず、操作感・実機性能は未検証として残す。
- branchからmain宛てDraft PR。main直接push/merge/automerge/配備/公開設定変更は行わない。提出直前に最新main/進行PRを再読し、他の作業を取り込まない。最終headのCIを確認し、失敗は原因修正後に再検査する。

## 未実装repoへの適用

現時点で飛行入力のないrepoでは、本契約・fixture・既存計画への差分のみを提出する。ゲーム本体/操作/保存の実装済みやブラウザー合格と主張しない。飛行入力がmainへ届いた段階で同じ契約のadapterを接続し、上記受入を実行する。進行中の独立実装PRは勝手に編集しない。
