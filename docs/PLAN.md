## 3. 再利用するもの・持ち込まないもの
元作をフォークして作品名だけ変える方法は採らない。依存と責務の小さな単位で複製し、出典commitを記録する。
- `src/aircraft.ts`: 翼端、胴体、カウル、風防、尾翼、日の丸、可動舵面、プロペラを再利用。1つのFactoryで形状・材質を共有。自機はhero、僚機/敵機は軽いdetailを使う。陣営は形の異なるHUD記号と機体の識別塗装で補助する。
- `simulation.ts` の `updateAircraftMotion` と宙返り: 65〜141m/s、巡航110m/s、低速旋回、高速の操縦減衰、ピッチ/バンクの指数応答、約5秒の宙返りと2秒の再使用待ちを抽出。これらは史実性能でなく元作のゲーム調整値。
- `input.ts`: 指ごとの操縦/ボタン所有、キャンセルとblur解除、キーボード互換を再利用。新作のUIだけへ接続。
- `flight-view.ts` / `flight-assist.ts`: FOV、追従offset、バンク伝達45%、投影と照準条件の共通化、手動優先と補助の滑らかさを維持。
- 弾のsweep判定とイベント一回性は仕組みを再利用し、陣営と艦の形へ拡張。
- 持ち込まない: 1,200m以下で10秒後に終了する空専用制約、定期増援、最後の敵の3秒後補充、元作のスコア/5分制限、名前・ランキング・Supabase接続、作品名・保存キー・公開URL・旧検査画像。
- 元作はライセンスを一般公開していない。所有者からの再利用依頼を本作への複製根拠とし、第三者への一般的利用許諾とは主張しない。Three.js等のNOTICEは保持する。

## 4. 構造
TypeScript＋Three.js＋Viteを使い、元作の固定依存を基準にする。物理エンジン、外部AIサービス、ネットワーク対戦、生成APIは不要。
- `types.ts`: team、entity id、航空機、艦、弾、確定イベント、結果を定義
- `flight.ts`: 元作由来の操縦・姿勢・速度・宙返り
- `simulation.ts`: 60Hzの唯一の状態所有者。入力→AI要求→移動→接触→射撃/弾→損傷→全滅/失敗→イベント
- `ai.ts`: 目標配分、追跡/攻撃進入/離脱/再進入、回避、対艦攻撃
- `mission.ts`: 初期配置、艦隊構成、HP、攻撃周期、調整値、ルール版。艦数候補は内部設定に閉じ、未依頼のモード選択を増やさない
- `aircraft.ts` / `ships.ts` / `scene.ts`: 状態を読む描画。見た目の海面波・傾斜で判定位置を変更しない
- `input.ts` / `main.ts`: 操作と画面遷移、固定更新、停止理由、再出撃の所有
- `audio.ts`: 確定イベントから有限の効果音。音の拒否でも視覚情報と本体は維持
- `records.ts`: 採用する場合だけ、作品固有の端末記録。通信層とは分離
- `tests/` / `scripts/`: 純粋ロジックとブラウザ検査。公開ビルドに状態改変用の試験入口を入れない

## 5. AI・戦闘・艦隊
- 味方は2機を迎撃寄り、2機を対艦寄りに仮配分。攻撃者が同じ標的へ集中しすぎないよう安定したid順と担当数で配分し、標的死亡時のみ即座に再選択する。
- 敵機は生存中の自機/僚機を狙う。正面からの攻撃後は離脱し再進入。味方/敵とも未来入力を見ず、同じ速度/旋回の限界で動く。
- 判断は固定tickの有界な間隔、移動は毎tick。描画FPSや実CPU時間でAIの強さを変えない。初期AI9機、180秒以降は最大AI12機。navmeshやWorkerを導入しない。
- 艦は船体、甲板、艦橋、主砲、煙突の読めるシルエットを手続き生成。U07追加改修により全艦を263m級へ統一し、武装の構成と仮設定をNAVAL_REFERENCE.mdへ記録。実在艦の精密再現は主張しない。
- 艦は低速で航行し、対空砲は射程・再射撃待ち・弾速を持つ実弾。照準は発射時点で確定、発射後の追尾や直接HP減算にしない。
- 航空機は相対移動sweep、艦は描画と同じ細くなる船体断面/上部構造boxへ線分判定。複数部位でも弾1発の命中は最初の1回のみ。
- 撃破した敵は目標から直ちに除外し、炎・煙・沈没は別の有限寿命。最後の撃破演出の終了をクリア計時の条件にしない。
- 自機の海面衝突は実高度へ対応。1,200m制約は削除し、低空警告と海面衝突の明確な表示へ置換する。

## 6. 海・カメラ・読みやすさ
- 朝〜日中の青い海、低い水平線、控えめな雲を基調にし、元作の灰緑色機体を主役にする。
- 海は連続面＋少数の波成分、斜光の反射、距離で弱まる細波。重い画面空間反射、全画面blur、過剰な透明板は初版に入れない。
- 艦の航跡、着弾の水柱、撃破の短い炎煙をイベントから出し、上限と寿命を持つプールで再利用。
- 自機後方斜め上の通常カメラで、機体、敵、艦、照準、残り目標が同時に読めるかを確認。画面外の敵はレーダー/方向表示へ。遠方を近距離の接触と偽って表示しない。
- 味方は丸/翼印、敵機は菱形、艦は横長記号など、色以外にも識別手段を付ける。敵残数は機と艦を別表示。
- 代表1艦・自機・海面の本編画面を仕上げてから10機と艦隊へ拡張する。拡大展示だけで描写完成としない。

## 7. スマートフォン操作とiPhone 17 Pro
- 端末固有の解像度を決め打ちせず、visualViewport/CSS表示矩形・safe-area・DPRを実測して配置する。
- 縦画面を初期設計、横画面も操作可能。上部に時間/敵残数/HP、下部に操縦空間と宙返り、停止/音は独立した44 CSS px以上のタップ範囲。
- 二本指、指を外で離す、pointercancel、回転、ブラウザUI伸縮、復帰、短い高さ、文字200%を検査。メニューはスクロールでき、本編のスワイプと混線しない。
- ゲーム開始、停止、再開、結果、再出撃、ホームの背後にある画面は入力を受けない。二重開始や古いキー保持を防ぐ。
- iPhone 17 Pro Safariを主な実機受入対象にするが、クラウドChromiumのタッチ/画面寸法模擬は実機合格と呼ばない。実機公開試験は後日の明示的な配備許可が必要。

## 8. 性能目標と測り方
以下は達成済みの値でなく仮目標。
- 実機の通常戦闘60fpsを目標にし、最混雑時も長い停止を避ける。まず計測してdraw call、画素量、透明重なり、CPU判定を切り分ける。
- 初期DPR上限1.5、hero1体＋初期軽量機9体、180秒後は最大軽量機12体、艦3隻。画質の軽量化は海の細波、装飾粒子、影へ限定し、敵数/弾/AI更新/時計は変えない。
- 安全な最大戦闘でrAF p50/p95/p99、CPU更新区間、draw calls/三角形/texture数を記録。GPU実測のないCPU区間をGPU時間としない。
- 初回compileと準備後を分け、10回再出撃後の資源数とイベント購読が基準へ戻ることを確認。
- 現在の作業環境は空き容量約587MB。大型素材・別ブラウザのダウンロードを避け、既存Chromiumを使う。必要な依存取得が入らなければ、その検査だけblockedとして報告する。

## 9. ランキングに関する後続判断
タイムアタックはまず確定時間をローカルに表示する。元作の高得点優先ランキングへ時間をそのまま送ってはならない。
オンライン連携を追加する前に、カイセン固有game_slug、名前必須/任意、短時間優先、同タイム順、上位件数、失敗の扱い、開始集計、ルール版/艦数別の母集団、サーバー検証、接続先、公開可否を利用者と確定する。
共通ハーネスの名前必須/上位10件も、元作の名前任意/上位30件も新作の承認にはならない。新規DB・本番送信・ゲーム登録は今回のコア実装と分離する。

### 実装の境界と段階
1. 艦体寸法/当たり判定/砲台位置/航跡を同じ定義へ合わせる。元作の12m翼幅・機体モデル・操縦感・追従カメラは維持。砲台ごとの照準・回転/仰角限界・装填/発射周期・砲身単位の射撃を導入。艦構造を貫いて発射せず、発射後は追尾しない重力弾道を用いる
2. 同じ海面式を表示と接触へ接続し、姿勢と前tickを含めて機体の接触を判定。低空警告を維持。航空機が砲撃だけで装甲艦を沈められるHP制と空中再装填はゲーム上の抽象化として保持し、新しい爆弾/魚雷/味方艦戦を追加しない
3. 有限弾倉・6秒再装填を固定時計へ、照準外周リング・メッセージ・残弾をHUDへ接続。増援は別ID/世代で一度だけ生成し、AI・描画・残数・回復・勝敗に含める
4. 同じ条件の通常艦隊接近画像、砲撃/低空接触、再装填と停止復帰を実経路で確認。13機と3/5/7隻の論理上限、実ブラウザ資源/描画統計を検査。iPhone実機の性能は引き続き未測定として区別する
