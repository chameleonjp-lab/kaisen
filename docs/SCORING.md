# カイセンの戦果貢献スコア

## 採用したルール

2026-10-05（日本時間）、利用者が「自分の与えた損傷への戦果点＋クリア＋速さ」を基本とする案を承認した。現行main `5f4565ee550ce9a1351516aa31ba9b5232c36e05` は通常加点がなく、Normalの誤射減点だけを0から差し引いていた。この変更は採点と結果内訳を実装する。飛行、機体／艦のHP、弾道、武器威力、敵AIは変えない。

| 項目 | 得点 |
|---|---|
| 初期敵機への戦果 | 1機500 × 自機による実損傷 ÷ その機の初期HP |
| 敵艦への戦果 | 1隻2,000 × 自機による装甲船体の実損傷 ÷ その艦の初期HP |
| クリア | 勝利時だけ12,000 |
| 速さ | 勝利時だけ max(0, 12,000 − 20 × 作戦秒数) |
| 被弾抑制 | 勝利時だけ500 × max(0, 1 − 累計実被ダメージ ÷ 80) |
| 味方への誤射 | Normal自機の実損傷1HPにつき−10 |
| 味方撃墜 | Normal自機による撃墜1機につき追加−1,500 |

失敗してもそれまでの戦果と誤射減点を残す。増援への損傷・撃墜は0点で、自機による増援撃墜の15HP回復は従来どおり。自機死亡・海面接触・衝突そのものに追加の減点はない。艦の砲座・上部構造の損傷や破壊に追加点を設けない。

通常4艦・初期敵5機の戦果上限は10,500点、時間0・無被弾・全戦果を仮定した合計上限は35,000点。時間点は600秒で0になる。艦1隻分の貢献2,000点は時間100秒分に相当し、速さが絶対優先という方式ではない。誤射がなければ、クリア12,000点だけでも戦果上限10,500点の失敗を上回る。誤射減点を含む全結果へこの優先を保証しない。

## 実損傷と一回性

- 開始時の初期敵と艦のID・初期HP・配点枠を保持する。初期敵は80HP、旗艦は4,000HP、通常艦は2,400HP。あとから変わる残HPや表示上の撃破件数を分母にしない
- 弾の威力そのものではなく、実際に減ったHPだけを記録する。過剰損傷、残骸、同じ減少の二重報告では増えない
- 僚機が最後の一撃を入れても、先に自機が削った割合は消えない。僚機・衝突・海面による消費は自機へ渡さない
- 同じ敵への消費済みHPは再利用せず、増援の新しいIDへ初期敵の配点枠を移さない。初期枠は5＋4件に限定され、増援回数で保持件数が増えない
- 爆弾直撃、起爆済み至近弾、魚雷の船体損傷は同じ記録経路を通る。砲座への副次損傷と二重計上しない
- 採点は描画イベントを購読して再加算する方式ではなく、シミュレーションの実HP変更と同時に行う。イベントの再表示・結果画面の再描画で増えない
- 被弾抑制は累計実被ダメージで計算する。回復して最終HP80でも、80HP以上被弾していれば0点
- 停止中の世界・時計・得点は凍結。死亡と全滅が同tickなら既存どおり敗北で、戦果は残り勝利ボーナスは付かない

HPの差分を取る際の浮動小数誤差だけは、HP規模の2 machine-epsilon以内で実際に適用した損傷値を保持して扱う。たとえば80−0.08の差分誤差で本来の0.5点を0点にしない。同じHPの再報告は0のままで、本当に0.5点未満の値を切り上げる最終丸めの補正はしない。

戦闘中は戦果と減点の丸め前の合計を保持する。終了時に全項目を小数のまま足し、最後に一度だけ既存表示と同じ `Math.round` を適用する。負の合計を0へ切り上げる処理は加えない。結果と内訳は凍結し、再出撃は新しい0点の記録から始まる。画面の内訳は小数2桁までの表示なので、丸め前の合計を使うことを併記する。

## 代表例と検査

以下は算式の固定入力例であり、利用者の実機画像からの再計算ではない。

| 入力例 | 得点 |
|---|---|
| 失敗、初期敵3機分の自機損傷、誤射なし | 1,500 |
| 180秒クリア、初期敵2.8機分・艦2.5隻分の自機損傷、累計被弾40 | 27,050 |
| 上記に誤射20HPと味方撃墜1機 | 25,350 |
| 同じ戦果と被弾、600秒クリア | 18,650 |
| 戦果なしで誤射12HPと味方撃墜1機、失敗 | −1,620 |

`tests/scoring.test.ts`は有限枠、初期HP固定、実弾／爆弾／魚雷／至近弾、僚機とどめ、過剰損傷、二重報告、増援と回復、衝突・海面、同時死亡、端数、負値、停止・確定・再出撃を検査する。既存の誤射・部位攻撃・増援・過去入力再生も新採点と照合する。UIは既存のEasy/Normalクリア・敗北経路で内訳、モード、縦横・文字拡大、操作到達性と結果凍結を確認する。実行状態は[VERIFICATION.md](VERIFICATION.md)と提出PRのChecksで区別する。

試験操縦のCI38回避修正前に、旧版と同じ6tickごとの入力を両方へ渡すNode診断では、勝敗・位置・HP・武器・敵AI・イベントを毎tick比較した。採点と結果の追加メタデータ以外は全滅まで完全一致。Easy135.7167秒は0→28,336点、Normal116.1167秒は0→29,021点となった。両方HP80だが累計被弾が異なるため、被弾抑制はEasy0／Normal293。この診断は内部観測で操縦する到達性検査であり、人の試遊や実機性能ではない。[比較データ](evidence/scoring-physics-parity.json)

CI38のNormal受入は、旧版にも同じ入力で再現する敵機衝突だった。原入力の敗北を保持し、製品の判定は変えず、試験操縦の安全な横回避だけを固定条件で検査した。[原因と比較](evidence/normal-collision-ci38.json)。既存の全滅受入を敗北でも合格に変えてはいない。

## モード・版と今後の接続

確定結果へmode、既存物理のrulesVersion `kaisen-air-sea-11`、採点版scoreRulesVersion `kaisen-contribution-1`を保持する。EasyとNormal、および旧0点方式の結果を同じ母集団へ混ぜない。

今回はオンラインランキング、名前入力、開始集計、送信、DBや公開設定を追加しない。将来の接続ではモード・ルール版・艦数、同点順、本人認証、開始と結果の関連付け、再送の一回性、サーバーでの検証を実契約に合わせて決める。クライアントの凍結だけでサーバー側の重複や不正を防げるとはしない。これはカイセン固有の採点であり、FightFlightへの自動同期対象ではない。
