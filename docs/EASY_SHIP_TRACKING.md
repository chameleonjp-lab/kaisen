# Easyの開始高度と艦への追尾

## 依頼と原因

2026-10-04、公開main `c750abdeb16a7ab8897fdd151271910e149c0662` への実機フィードバックは「イージーモードは、もう少し上空からスタート、戦艦へのカメラの追尾補正が強すぎます。弱めてください」。調整値を指定されたものとは扱わない。

開始高度は両モード220mだった。`getFlightCameraPose`には敵や船を見る処理はなく、機体の姿勢へ固定offset/FOVで追従する。`getFlightAssist`が画面内で最も近い対象を選び、照準円の外へ同じ強さで自動操舵していた。低い海上目標へ機首が下がり、その結果、視点が大きく俯く。機体と違う方向を見る別カメラを追加せず、この作用点で船の補助だけを減らす。

## 比較と採用値

Easyの開始高度を300mにし、僚機の相対編隊高度を保持する（全機+80m）。Normalは220m。船が選ばれた場合だけ既存`assistFade`へ0.25を掛け、yawと絶対pitchへの補正を弱める。最終の手動入力を倍率で小さくしない。標的の選び方も変えない。

同じモデル/カメラで初期の艦照準点は、220/300/320/350m時に画面正規化yが−0.658/−0.913/−0.977/−1.072。350mでは艦の照準点が画面外になり、全体条件では見える航空機へ対象が切り替わる。300mは320mより画面端の余裕があり、+80mの上空開始となる。ただし前景艦の下部は初期画面で切れ得る。実画面でも開幕と通常追尾を確認する。

seed73、393×852相当、60Hz、無操作で最大6秒進めた比較:

| 開始高度/艦補助 | 最大俯角 | 最大高度低下 | 終了状態 |
|---|---:|---:|---|
| 220m / 100%（公開版） | 48.86° | 193.73m | 艦衝突 |
| 220m / 25%（補助だけ変更） | 9.75° | 38.16m | 飛行中 |
| 300m / 100%（高度だけ変更） | 52.56° | 268.50m | 艦衝突 |
| 300m / 15% | 5.32° | 10.67m | 飛行中 |
| **300m / 25%（採用）** | **10.04°** | **30.27m** | **飛行中** |
| 300m / 35% | 15.97° | 65.27m | 飛行中 |
| 320m / 25% | 10.06° | 27.33m | 飛行中 |

高度だけを上げても強い自動降下は解消しなかった。25%は補助を残しつつ、35%より自動降下を減らす中間案。全体の実ルールに加え、対象を船だけに絞ったオフライン診断でも同じ傾向を確認した。後者は診断fixtureであり、ブラウザ受入の敵を減らすものではない。詳細は[evidence/easy-ship-tracking.json](evidence/easy-ship-tracking.json)。長時間の無操作安全や無条件の勝利を保証しない。

## 維持する範囲

- 航空機対象の補助倍率は1。同一姿勢/入力の54条件で公開版と一致
- Normalは3seed×600tickの全状態比較で公開版と一致。初期配置/速度/入力/カメラ/弾の条件は同じ
- Easyの弾補正35%、上限0.028rad、捕捉gate0.16は維持。照準内自動射撃と発射後の直線弾道も同じ
- カメラoffset、FOV、バンク伝達、機体モデル、物理操縦、offscreen応答、射程/HP/艦/兵装、得点と順位条件は維持
- 補助の既存slew（turn2.5/s、climb1.5/s）は維持。対象切替の直後に以前の補助が短く残るが、突然視点を跳ねさせるresetは追加しない。強い手動入力/逆方向入力による解除を実stepで検査
- Faitofuraitoへ船・海戦開始高度は同期しない。共通の弾補正35%/0.028radの同期元は引き続きc750

ルール識別は`kaisen-air-sea-9`。旧入力fixtureの記録は変更せず、新ルールでも決定性を検査する。オンラインランキング・保存先の変更はない。

## 受入と検査の限界

`tests/easy-ship-tracking.test.ts`で初期/編隊整合、同一幾何の船倍率、手動優先、混在標的、残留補助と切替、3seed×縦横/短画面の実step開幕を検査。`browser-tests/easy-ship-tracking.spec.ts`は通常UIで開幕、6秒の無操作追尾、実タッチによる上昇、停止/再出撃、Normal220mを確認する。スクリーンショットは実際に一時停止し、撮影時だけ停止メニューを隠す。ゲーム状態・時間・結果へ書き込まない。

関連単体に続き最終候補で全体検査をまとめる。実ブラウザ結果はPRとChecksで確定する。CIの模擬画面・ソフトウェアGPUをiPhone17Pro実機の操作感・熱・長時間描画の合格とは扱わない。
